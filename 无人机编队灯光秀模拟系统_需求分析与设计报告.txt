一、软件系统需求分析
1.1 项目背景与选题依据
无人机编队灯光秀作为一种新兴的表演艺术形式，已在国内外大型活动中广泛应用 --  -- 从春晚到奥运会开幕式，无人机编队以夜空为画布，通过精确的轨迹控制与灯光变幻，呈现出震撼的视觉盛宴。本课程设计选题"无人机编队灯光秀模拟系统"（选题18），要求在C/C++语言环境下，实现一个具备编队初始化、轨迹设计、灯光控制、实时模拟、安全检测和数据回放等核心功能的模拟仿真系统。
本系统以Windows控制台为渲染平台，采用字符画（CHAR_INFO帧缓冲+WriteConsoleOutputW）方案，无需任何第三方图形库，完全基于标准C/C++和Win32 Console API实现。系统支持500架无人机同时在120x40字符格的舞台上运行，提供15种几何编队图案、文字点阵编队、BMP图片编队、8种灯光颜色、5种动态灯光特效，以及安全检测、历史回溯等完整功能。
根据课程设计任务书（commands.txt）的要求，本课题需实现的核心功能包括：
（1）编队初始化：设置无人机数量、初始位置和飞行高度；
（2）轨迹设计：输入关键坐标点，让无人机按直线自动移动，完成简单队形变换；
（3）灯光控制：控制无人机灯光开关、颜色切换和闪烁效果；
（4）实时模拟：在终端动态显示无人机位置和灯光状态；
（5）安全检测：判断无人机是否越界、距离过近并给出提示；
（6）数据回放：读取保存的轨迹，重新演示整个灯光秀过程。

二、系统分析与设计
2.1 系统架构设计
系统采用"分层模块化"架构，分为四层：
（1）表示层（Presentation Layer）：graphics模块 + ui模块，负责画面渲染和用户输入处理。graphics模块实现CHAR_INFO帧缓冲和WriteConsoleOutputW方案的完整控制台渲染管线；ui模块通过_kbhit/_getch实现非阻塞键盘输入检测。
（2）业务逻辑层（Business Logic Layer）：drone模块 + formation模块 + trajectory模块 + light模块 + safety模块，负责无人机实体管理、编队图案生成、航点轨迹插值、灯光效果计算、安全检测等核心仿真逻辑。
（3）数据持久层（Data Persistence Layer）：file_io模块，负责轨迹数据和编队信息的二进制文件读写，支持数据回放功能。
（4）控制调度层（Control Layer）：controller模块，作为系统的"指挥中心"，拥有所有子系统的状态，主循环每帧依次执行用户输入检测-->轨迹更新-->灯光特效更新-->安全检测-->渲染-->帧率控制。
架构设计的核心原则：
:: 单一职责：每个模块只负责一个明确的功能领域
:: 依赖倒置：所有模块依赖common.h的抽象类型，不互相依赖
:: 状态封装：所有运行时状态封装在Controller结构体中，通过指针传递
:: 无全局变量：严格遵循课程要求，所有数据通过参数传递

               ┌──────────────────────────────────┐
               │                                  │
               ▼                                  │
       ┌──────────────┐     S(开始)     ┌──────────────┐

 ConsoleColor drone_get_current_color(Drone* drone, int delta_ms) {
     switch (drone->light.mode) {
     case LIGHT_OFF:    return CON_BLACK;
     case LIGHT_STEADY: return color_table[drone->light.color];
     case LIGHT_BLINK:
         drone->light.blink_timer += delta_ms;
         if (blink_timer >= blink_interval) {
             drone->light.is_visible = !drone->light.is_visible;
             blink_timer -= blink_interval;  // 保留余数，精确计时
         }
         return is_visible ? color_table[color] : CON_BLACK;
     }
 }

（3）文字编队生成算法：
文字编队通过Windows GDI将文本渲染到内存位图，然后降采样为二值点阵映射到无人机。流程如下：
 gen_text(center, char_size, text, count, out[])
   │
   ├─ ① 创建内存DC + 兼容位图（12x12 per_char 像素格）
   ├─ ② 用GDI TextOutW 逐字渲染（LOGFONT字体高度=char_size）
   ├─ ③ GetPixel 逐像素采样，二值化（暗色=1 亮色=0）
   ├─ ④ 密度自适应: 可用无人机多 --> density=3（9架/像素簇）
   │                可用无人机少 --> density=1（1架/像素，骨架）
   └─ ⑤ 将二值点阵映射为无人机目标坐标 --> 写入out[]
（4）BMP图片编队生成算法：
图片编队通过GDI加载BMP位图，缩放后逐像素采样，将暗色像素映射为无人机位置。流程如下：
 gen_image(center, scale, filename, count, out[])
   │
   ├─ ① GDI LoadImage(filename, IMAGE_BITMAP) 加载BMP
   ├─ ② StretchBlt 缩放到目标尺寸（scale控制）
   ├─ ③ GetPixel 逐像素采样，取最小值（暗色判定阈值=128）
   ├─ ④ 非0像素 --> 映射为无人机坐标
   └─ ⑤ 写入out[]。若暗色点数 > 可用无人机数 --> 等间距采样
（5）扩展新图案的方法：
只需三步：（1）编写gen_xxx()生成器函数；（2）在pattern_generate()的switch中添加case；（3）在g_pattern_list数组中注册。体现了良好的开闭原则（对扩展开放，对修改封闭）。

     // 1. 出发延迟检查
     if (traj->departure_delay > 0) { delay -= delta_ms; return 1; }
     // 2. 轨迹完成检查
     if (current_index >= waypoint_count) return 0;
     // 3. 计算到目标距离
     float dx = target.x - drone->position.x;
     float dy = target.y - drone->position.y;
     float dist = sqrt(dx*dx + dy*dy);
     float step = speed * delta_ms / 1000.0f;
     // 4. 到达判定（<0.5格=到达）
     if (dist < 0.5f) {
         吸附到精确目标 --> 同步灯光 --> current_index++ --> return;
     }
     // 5. 沿方向向量移动
     drone_move(drone, (dx/dist)*step, (dy/dist)*step, 0);
     return 1;  // 仍在运动
 }

碰撞避让算法：
 void safety_avoid_collisions(fleet[], count, zone, strength) {
     for i in 0..count-1:
         for j in i+1..count-1:
             dist = DISTANCE(fleet[i], fleet[j])
             if (dist < zone->min_distance/2 && dist > 0.001):
                 force = (avoid_dist - dist) / avoid_dist * strength
                 排斥力推开: fleet[i] += (nx*force, ny*force)
                             fleet[j] -= (nx*force, ny*force)
 }

7.2 编码规范
本系统严格遵循统一的编码规范，确保代码可读性和可维护性：
（1）命名规范：函数名使用snake_case（如drone_create、traj_update_fleet）；类型名（结构体/枚举）使用PascalCase（如Drone、LightColor、SafetyResult）；常量使用UPPER_SNAKE_CASE（如MAX_DRONE_COUNT、SAFETY_MIN_DISTANCE）；宏函数使用UPPER_SNAKE_CASE。
（2）注释规范：每个文件头部有@file/@brief说明；每个函数有@brief/@param/@return Doxygen风格注释；关键算法有详细的行内注释解释原理；常量定义有注释说明用途和单位。
（3）代码组织：头文件使用#ifndef/#define/#endif防重复包含；每个.h文件对应于一个.cpp实现；函数声明按"生命周期-->操作-->查询-->工具"分组；结构体字段按"标识-->位置-->状态-->标记"排序。
（4）内存管理：所有动态分配有对应的释放函数；使用SAFE_FREE宏防止悬挂指针和double-free；批量创建失败时回滚已分配的资源（如drone_create_fleet）；使用堆分配+指针传递代替全局变量。

8.2 分工说明
冯格（核心仿真引擎）：负责无人机实体（drone）、灯光控制（light）、编队图案生成（formation）、轨迹插值（trajectory）、安全检测（safety）五个模块的设计与实现。总计约1952行代码。主要技术难点：15种几何图案的生成算法、5x7点阵文字编队、BMP图片降采样、逐帧线性插值轨迹引擎、O(n²)碰撞检测与避让。
陈七政（图形渲染与交互）：负责图形渲染（graphics）、用户输入（ui）、文件读写（file_io）、主控制器（controller）四个模块的设计与实现。总计约2103行代码。主要技术难点：CHAR_INFO帧缓冲+WriteConsoleOutputW双缓冲渲染方案、UTF-8多字节字符解析、120x40屏幕布局设计、主循环帧率控制、命令处理状态机、编队历史环形缓冲区。
共同工作：公共头文件（common.h）的类型定义和维护、程序入口（main.cpp）、编译脚本（build.bat）、本报告撰写。
协作机制：common.h定义统一接口，controller.h定义状态容器结构体，两人各自开发独立模块，通过controller集成联调。所有类型由common.h统一，避免了接口不匹配问题。

九、测试与调试
9.1 测试策略
本系统在开发过程中采用了分层测试策略：
（1）单元测试：每个模块开发完成后独立测试。例如：测试15种图案生成器的输出坐标是否在合理范围内；测试轨迹插值能否正确到达目标航点；测试闪烁逻辑的占空比是否为50%。
（2）集成测试：将相关模块组合测试。例如：formation+trajectory联合测试编队切换是否流畅；controller+graphics联合测试画面渲染是否正常。
（3）系统测试：完整运行流程测试。包括：启动-->欢迎界面-->按S开始-->切换所有17种图案-->切换所有8种颜色-->测试所有5种灯光特效-->调节速度-->文字编队-->图片编队-->历史回溯-->安全检测触发-->按ESC退出。
（4）边界测试：无人机数量边界（0架、1架、500架、超500架）；图案参数边界（0缩放、负数缩放、超大缩放）；轨迹边界（0航点、200航点）；安全检测边界（无人机在边界线上、两机完全重叠）。

十、总结与展望
10.1 项目总结
本课程设计项目"无人机编队灯光秀模拟系统"严格按照课程设计任务书（commands.txt）要求，完成了全部6项核心功能需求和10项扩展功能。系统以C++11语言实现，编译环境为GCC/MinGW-w64，仅使用Windows Console API，无任何第三方图形库依赖，完全符合课程"仅用标准C和其中的图形库"的要求。
系统实现了以下主要技术成果：
（1）完整的控制台渲染管线：基于CHAR_INFO帧缓冲+WriteConsoleOutputW的双缓冲方案，实现120x40字符格的零闪烁实时渲染，20fps稳定帧率。
（2）17种编队图案生成器：15种几何图案（圆/方/三角/菱形/五角星/五边形/六边形/心形/螺旋/直线/箭头/十字/弧形/网格/随机）+ 文字点阵编队（GDI渲染+降采样）+ BMP图片编队（GDI加载+像素采样），采用策略模式统一调度。
（3）精确的轨迹插值引擎：逐帧线性插值，浮点坐标保证平滑移动，到达判定阈值0.5格，随机出发延迟避免空中交叉。
（4）完善的安全检测系统：实时边界越界检测（O(n)）+ 间距碰撞检测（O(n²)）+ 碰撞避让排斥力，违规信息在画面和日志面板双重反馈。
（5）丰富的灯光效果：8种颜色 + 常亮/闪烁模式 + 5种动态特效（波浪/流水/交替/彩虹流水/颜色渐变）。
（6）严格的工程化实践：10个模块分离，头文件/源文件分离，统一编码规范，无全局变量，内存安全释放。
10.2 改进方向
尽管系统已实现了丰富的功能，但仍有以下可改进的方向：
（1）中文文字编队支持：当前文字编队仅支持英文和数字（A-Z、0-9），中文渲染因GDI字体高度计算问题暂不支持。后续可通过调整字体度量方式或使用Uniscribe布局引擎来支持中文。
（2）数据回放功能完善：file_io模块已定义了二进制文件格式框架，但加载和回放功能仍标注为TODO待实现。
（3）3D视角支持：当前系统为2D俯视图视角，可扩展为伪3D等距视角，增加高度维度的视觉呈现。
（4）更复杂的轨迹规划：当前轨迹仅为直线插值，可扩展为贝塞尔曲线、B样条等平滑轨迹，使队形变换更流畅优美。
（5）音频同步：可增加BGM播放与灯光秀动作的时间轴同步，实现完整的声光表演。
（6）网络同步：可扩展为多机同步显示，模拟大规模无人机编队表演的控制系统。
